# 가설: 윈도우 9·10 (agree55) 규칙 정리

**가설 키**: `first_anchor_window9_10_agree55`  
**표시 이름**: 윈도우 9,10 (agree55)  
**검증 함수**: `validate_first_anchor_window9_10_agree55_cp`

---

## 1. 검증 시작 및 앵커 진행

| 규칙 | 설명 |
|------|------|
| **첫 앵커부터 검증** | 전체 스트링에서 **첫 번째 앵커**(change-point 직후 위치)부터 검증을 시작한다. |
| **종료 조건 충족 시 다음 앵커** | 현재 앵커에서 종료 조건이 충족되면 해당 앵커 검증을 마치고 **다음 앵커**로 이동한다. |
| **앵커 순차 이동** | 앵커는 인덱스 순서대로 처리한다. (`anchors[0]` → `anchors[1]` → …) |

---

## 2. 앵커당 검증 범위

| 규칙 | 설명 |
|------|------|
| **윈도우 9과 10만 검증** | 각 앵커에서는 **window_size 9**와 **window_size 10**만 사용한다. (11, 12, 13, 14는 사용하지 않음) |
| **검증 순서** | 앵커 내에서는 **윈도우 9**를 먼저 검증하고, 다음으로 **윈도우 10**을 검증한다. |

위치 계산: `pos = anchor + window_size - 1`  
- 윈도우 9 → `pos = anchor + 8`  
- 윈도우 10 → `pos = anchor + 9`

---

## 3. 예측값 사용 조건 (미충족 시 스킵)

예측을 **사용**하려면 아래 조건을 **모두** 만족해야 한다. 하나라도 불만족하면 해당 스텝은 **스킵**한다.

| 조건 | 설명 |
|------|------|
| **(3a) 빈도·가중치 예측값 일치** | `simulation_predictions_change_point`에서 같은 (window_size, prefix, threshold)에 대해 **빈도 기반**과 **가중치 기반**의 `predicted_value`가 **같아야** 한다. |
| **(3b) 빈도·가중치 신뢰도 모두 임계값 이상** | 빈도 기반 행의 `confidence` ≥ **빈도 임계값**(기본 51%) **그리고** 가중치 기반 행의 `confidence` ≥ **가중치 임계값**(기본 51%). 두 임계값을 각각 설정할 수 있으며, **둘 다 충족**할 때만 예측 사용. |
| **(3c) 스킵 처리** | 위 (3a)(3b) 중 하나라도 불만족 시 해당 (anchor, window_size, position)는 **예측으로 사용하지 않고 스킵**한다. `total_predictions`에 포함하지 않으며, history에는 `skipped=True` 및 `skip_reason`으로 기록한다. |

- 데이터 소스: `simulation_predictions_change_point`  
- 동일 (window_size, prefix, threshold)에 대해 **method = '빈도 기반'** 과 **method = '가중치 기반'** 두 행을 모두 조회하여 비교한다.  
- 테이블 생성 시 `methods=("빈도 기반", "가중치 기반")` 둘 다 저장되어 있어야 한다.

---

## 4. 조기 종료 조건

| 규칙 | 설명 |
|------|------|
| **윈도우 9에서 예측 존재 + 일치** | **윈도우 9**를 검증할 때, (규칙 3을 만족하는) 예측값이 존재하고 그 예측값이 **실제값(actual)과 일치**하면 → **즉시 해당 앵커 검증 종료**. |
| **윈도우 10 생략** | 위 조건이 충족되면 같은 앵커에서 **윈도우 10은 검증하지 않고** 다음 앵커로 이동한다. |
| **그 외** | 윈도우 9에서 조기 종료가 아니면, 같은 앵커에서 **윈도우 10까지 검증**한 뒤 다음 앵커로 이동한다. |

---

## 5. 앵커 중첩 시 이전 앵커만 검증

| 규칙 | 설명 |
|------|------|
| **동일 position 중복 검증 금지** | 같은 **position**을 서로 다른 (앵커, 윈도우) 조합이 커버할 수 있다. (예: position 14 = 앵커 5 + 윈도우 10, 또는 앵커 6 + 윈도우 9) |
| **이전 앵커만 검증** | 이렇게 **중첩**되는 경우, **먼저 도달하는(앵커 인덱스가 작은) 앵커**에서만 그 position을 검증한다. **다음 앵커**에서는 이미 검증된 position을 **다시 검증하지 않는다**. |
| **구현** | `validated_positions` set으로 이미 검증(또는 스킵)한 position을 기록하고, 새 (anchor, window_size)에서 계산한 `pos`가 이미 set에 있으면 해당 스텝을 **수행하지 않는다** (total_steps·history에 포함하지 않음). |

## 6. 요약 표

| # | 규칙 | 요약 |
|---|------|------|
| 1 | 검증 시작·진행 | 첫 앵커부터, 종료 조건 충족 시 다음 앵커로 순차 이동 |
| 2 | 검증 범위 | 앵커당 윈도우 9, 10만 검증 (9 → 10 순서) |
| 3 | 예측 사용 조건 | 빈도·가중치 예측값 일치, 빈도 신뢰도 ≥ 빈도 임계값(기본 51%) **및** 가중치 신뢰도 ≥ 가중치 임계값(기본 51%); 미충족 시 스킵 |
| 4 | 조기 종료 | 윈도우 9에서 예측 존재·일치 시 해당 앵커 종료(윈도우 10 생략) |
| 5 | 앵커 순서 | 앵커는 순차적으로만 이동 |
| 6 | 앵커 중첩 | 같은 position은 이전 앵커에서만 검증, 다음 앵커에서는 생략 |

## 8. 스킵 사유 (skip_reason) 예시

- `"예측 테이블에 값 없음"` — 해당 (window_size, prefix, threshold)에 빈도/가중치 행이 없음  
- `"빈도/가중치 중 하나 없음"` — 한쪽 method만 존재  
- `"빈도/가중치 예측값 불일치"` — 두 method의 predicted_value가 다름  
- `"신뢰도 부족 (빈도 X% < Y%, 가중치 ...)"` — 빈도 또는 가중치 confidence가 각 임계값 미만 (둘 다 충족해야 함)
