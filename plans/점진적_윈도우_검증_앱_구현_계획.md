# 점진적 윈도우 검증 시뮬레이션 앱 구현 계획

## 요구사항 정리

| 항목            | 내용                                                |
| ------------- | ------------------------------------------------- |
| 기준점(Baseline) | 2026년 1월 25일 **이전** 데이터 = 초기 학습셋                  |
| 증분 단위         | 1월 25일 **이후** 데이터를 **일 단위**로 분할                   |
| REQ-701       | 매 스텝에서 이전 검증 데이터를 다음 스텝 학습에 포함(누적 학습, 학습셋 점진적 확장) |
| REQ-702       | 검증 데이터 = 현재 학습 직후의 **최소 증분 단위**(1일치)만 사용          |


## 현재 코드베이스 요약

- **데이터**: change_point/change_point_ngram.db 연동 `preprocessed_grid_strings` 테이블에 `id`, `created_at`, `grid_string` 등 존재. svg_parser_module.py에서 `created_at` 컬럼 및 인덱스 정의.
- **검증 흐름**: change_point_hypothesis_module.py의 `generate_simulation_predictions_table(cutoff_grid_string_id)`가 `id <= cutoff`로 학습해 `simulation_predictions_change_point`에 저장하고, `batch_validate_first_anchor_extended_window_v3_cp` / `batch_validate_first_anchor_window9_10_cp`가 `id > cutoff`인 **전체**를 검증함.
- **참고**: walk_forward_simulation_cp.py는 건수 기준 expanding window(학습 → 검증 → 학습에 검증 추가 반복)를 이미 구현. 일 단위·날짜 기준 분할은 없음.

## 설계 개요

- **일 단위 분할**: `preprocessed_grid_strings`에서 `date(created_at)` 또는 `strftime('%Y-%m-%d', created_at)`로 그룹해, `>= '2026-01-25'`인 날짜를 정렬한 목록을 구한다.
- **스텝별**
  - 학습: `created_at < 해당_검증_일` 인 모든 행 (즉 해당 일 **직전**까지 누적).
  - 검증: 해당 **해당_검증_일** 하루치만 (REQ-702).
- **구현**: 각 스텝에서 `train_cutoff_id = max(id) WHERE created_at < 해당_검증_일`, `validation_ids = id WHERE date(created_at) = 해당_검증_일` 로 구한 뒤, 기존 단일 검증 함수를 해당 일 id만 순회 호출.

## 구현 원칙: 기존 코드와 완전 독립

- **기존 모듈 수정 금지**: change_point_hypothesis_module.py, change_point_prediction_module.py, svg_parser_module.py 등 기존 파일에는 **한 줄도 추가·수정하지 않음**.
- **신규 파일만 추가**: 점진적 검증 앱과 그 전용 유틸은 **새 파일**로만 구현. 기존 앱·가설 테스트·라이브 게임 앱은 이 새 파일을 import하지 않으므로 동작에 영향 없음.
- **기존 API만 호출**: 새 앱은 기존에 이미 있는 함수만 **읽기/호출**한다.
  - 예측 테이블: `generate_simulation_predictions_table(cutoff_grid_string_id, ...)` 그대로 호출.
  - 검증: 기존 **단일 grid 검증** 함수 `validate_first_anchor_extended_window_v3_cp(gid, cutoff_grid_string_id, ...)`, `validate_first_anchor_window9_10_cp(gid, cutoff_grid_string_id, ...)`를 **새 앱 쪽 루프**에서 해당 일의 `validation_ids`에 대해 반복 호출하고, 결과만 새 앱에서 집계.

## 구현 항목

### 1. 일 단위 날짜·ID 조회 유틸 (신규 모듈에만 구현)

**파일**: change_point/incremental_validation_utils.py (신규)

- `get_incremental_validation_dates(baseline_date='2026-01-25')`
  - `preprocessed_grid_strings`에서 `date(created_at) >= baseline_date` 인 **서로 다른 날짜**를 `ORDER BY date` 로 반환 (리스트 of date 문자열). DB 연결은 `svg_parser_module.get_change_point_db_connection()` 호출로만 사용.
- `get_train_cutoff_id_for_date(validation_date)`
  - `validation_date` **미만**의 모든 행에 대해 `max(id)` 반환.
  - SQL: `SELECT max(id) FROM preprocessed_grid_strings WHERE date(created_at) < date(?)` (SQLite `date()`/`strftime` 사용).
- `get_validation_ids_for_date(validation_date)`
  - 해당 날짜 하루치 id 목록.
  - SQL: `SELECT id FROM preprocessed_grid_strings WHERE date(created_at) = date(?) ORDER BY id`.
  - 해당 일에 id가 없으면 빈 리스트 반환.

위 함수들은 **새 유틸/앱 파일 안에서만** 정의하고, 기존 모듈에는 추가하지 않음.

### 2. 점진적 시뮬레이션 루프 (앱 내부)

**위치**: change_point/change_point_incremental_validation_app.py 내부

- 입력: method, threshold, baseline_date. **2가설 동시** (V3, 윈도우 9,10).
- 절차:
  1. `get_incremental_validation_dates(baseline_date)` 로 검증할 날짜 리스트 획득.
  2. 각 `validation_date`에 대해:
    - `train_cutoff_id = get_train_cutoff_id_for_date(validation_date)` (해당 일 **전**까지 누적 → REQ-701).
    - **기존 함수 그대로 호출**: `generate_simulation_predictions_table(train_cutoff_id, window_sizes=(9,10,11,12,13,14), method=..., threshold=...)` (기존 모듈 수정 없음).
    - `validation_ids = get_validation_ids_for_date(validation_date)`.
    - **기존 단일 검증 함수만 사용**: `validation_ids`를 순회하며 **V3**와 **윈도우 9,10** 두 함수 각각 호출. (같은 일자·같은 데이터로 2가설 동시 검증.)
    - 해당 일 결과(요약/상세) 저장·누적.
  3. 전체 스텝 결과를 합쳐 일별·전체 요약 및 **2가설 비교** 데이터 반환.

에러 처리: 특정 일에서 예측 테이블 생성/검증이 실패하면 해당 스텝만 스킵하거나 로그 후 계속 진행.

### 3. 별도 Streamlit 앱 (신규 파일만)

**파일**: change_point/change_point_incremental_validation_app.py (신규)

- **페이지**: “점진적 윈도우 검증 시뮬레이션” 제목, 기준일(기본 2026-01-25), 예측 방법·임계값 설정. **2가설 동시 시뮬레이션** (가설 선택 없이 V3 vs 윈도우 9,10 동시 실행).
- **실행 버튼**: “시뮬레이션 실행 (2가설 동시)” 클릭 시 점진적 루프 실행. 진행률(진행 중인 날짜, N/M 일 완료) 표시.
- **데이터 소스**: 기존 모듈을 **호출만** 함. 동일 DB 사용. 기존 앱 코드는 수정하지 않음.

#### 일자별 시뮬레이션 결과 표시 방식 (상세)

**1) 루프 반환 데이터 구조**

- `daily_summaries`: 리스트. 각 원소는 **한 날짜**에 대한 **2가설 비교** 요약 dict.
  - `date`, `validation_count`
  - `v3_avg_accuracy`, `v3_max_consecutive_failures`, `v3_total_predictions`, `v3_total_skipped`
  - `w910_avg_accuracy`, `w910_max_consecutive_failures`, `w910_total_predictions`, `w910_total_skipped`
- `daily_results`: 리스트. 각 원소는 **한 날짜**의 상세.
  - `date`, `v3_results`, `w910_results` (각각 validate_*_cp 반환값 리스트).
- `overall_summary`: `v3`, `window9_10` 각각에 대한 전체 누적 요약.

**2) 화면 구성 (Streamlit)**

- **상단 — 전체 누적 요약 비교**
  - 2열: V3 요약 vs 윈도우 9,10 요약 (검증 건수, 평균 정확도, 최대 연속 불일치, 총 예측/스킵).
- **중단 — 일자별 비교 테이블**
  - 컬럼: 날짜 | 검증 건수 | V3 평균정확도(%) | V3 최대연속불일치 | 윈도우9,10 평균정확도(%) | 윈도우9,10 최대연속불일치.
  - 한 행 = 한 날짜. 2가설을 나란히 비교.
- **하단 — 일자별 상세 (펼침)**
  - 각 날짜마다 expander, 그 안에 탭 2개: “V3” / “윈도우 9,10”. 각 탭에 해당 일의 grid_string별 결과 테이블.

**3) 표시 예시 (일자별 비교 테이블)**

| 날짜       | 검증 건수 | V3 평균정확도(%) | V3 최대연속불일치 | 윈도우9,10 평균정확도(%) | 윈도우9,10 최대연속불일치 |
| ---------- | --------- | ---------------- | ----------------- | ------------------------ | ------------------------- |
| 2026-01-25 | 12        | 85.2             | 3                 | 84.1                     | 2                         |
| 2026-01-26 | 8         | 88.1             | 2                 | 87.5                     | 2                         |

앱은 기존 가설 테스트 앱·라이브 게임 앱과 분리된 “별도 앱”으로만 두며, **기존 코드 동작에 영향 없음**.

### 4. 데이터 요구사항 충족 체크

- **REQ-701**: 매 스텝의 `train_cutoff_id`를 “해당 검증일 **미만**까지의 max(id)”로 두므로, 이전 스텝에서 검증에 쓴 데이터(해당 일)는 다음 스텝의 학습에 포함됨. 충족.
- **REQ-702**: 검증은 `get_validation_ids_for_date(validation_date)`로 **해당 일 id만** 넘겨, 새 앱 루프에서 단일 검증 함수만 호출하므로 최소 증분 단위(1일)만 검증. 충족.
- **기준점**: baseline_date(기본 2026-01-25) 이전 = 초기 학습셋; 첫 검증일을 2026-01-25로 두면 “1월 25일 이후를 일 단위로” 분할과 일치.

**정리**: 새 검증 앱은 **기존 코드와 독립**으로, 신규 파일 추가만으로 구현하며 기존 코드 동작에는 영향을 주지 않음. **목적**: V3와 윈도우 9,10 두 가설을 동시에 시뮬레이션하여 결과를 비교.

## 파일 변경 요약 (기존 코드 수정 없음)

| 대상 | 작업 |
|------|------|
| change_point/change_point_incremental_validation_app.py | **신규**: Streamlit UI, 2가설 동시 점진적 루프, 일별·전체 결과 및 비교 표시 |
| change_point/incremental_validation_utils.py | **신규**: `get_incremental_validation_dates`, `get_train_cutoff_id_for_date`, `get_validation_ids_for_date`. 앱에서만 import. |
| 기존 모듈 (hypothesis_module, prediction_module, svg_parser_module 등) | **수정 없음**. 새 앱이 기존 API를 읽기/호출만 함. |

실행: `streamlit run change_point/change_point_incremental_validation_app.py` (프로젝트 루트 기준).

## 참고 사항

- `created_at`이 NULL이거나 형식이 제각각이면 일 단위 분할이 틀어질 수 있음. 앱 초기 로드 시 “기준일 이후 날짜 개수” 또는 샘플 날짜를 한 번 보여주면 운영 시 확인하기 좋음.
- 일별로 `generate_simulation_predictions_table`를 호출하고, 같은 일자에 V3·윈도우 9,10 두 검증을 수행하므로 스텝 수가 많으면 실행 시간이 길어질 수 있음. 진행률 표시와 (선택) 캐시/재실행 정책을 두는 것을 권장.
